# Personal Duo Pet：双角色桌宠

当前路线：**DeepSeek 编剧 → 规则校验 → 独立语义 Review（最多一次修订复审）→ 台词/动作场景 → GPT-SoVITS 合成（暂关闭）→ 表演归档草稿 → 人工预览/局部修订 → 确认加入轮播 → 离线自动播放**。

离线不接受用户提问，也不在线生成台词。无需安装 Ollama 或下载本地语言模型。两个角色共用一次编剧请求，通过角色 ID 区分，不需要两个大语言模型。

## 启动

也可双击项目根目录的 `Start-Personal-Pet.cmd`。

项目根目录：

```powershell
npm.cmd run personal
```

依赖首次准备（双角色入口无需上游原生模块）：

```powershell

node node_modules/electron/install.js
```

GitHub 下载慢时可临时使用 Electron 国内镜像，下载仍由 Electron 安装器核对校验和：

```powershell

node node_modules/electron/install.js
```

## 播放窗口与编辑窗口

启动后显示两个真实 Live2D 角色与对话气泡，播放窗口和编辑窗口相互独立。

播放窗口沿用上游原生方案：Electron transparent/frame:false、页面透明、顶栏原生拖动区域；静止时无常驻底色。拖动窗口或人物时出现半透明浮层和浮动阴影，松手后约 220 毫秒淡出。整体移动请拖动顶部原生把手；人物可以单独拖动，姓名标签已移除。完全透明空白像素在 Windows 上可能直接穿透，不能把它当作稳定的拖动入口。

两个角色采用靠近的半身裁切，渲染倍率至少 2×，并使用新的半身布局位置存档以避免旧全身坐标干扰。播放窗口默认 480×480，编辑窗口默认 560×580，最大尺寸均限制为 600×600（逻辑像素）。播放窗口右上角 × 和编辑窗口「退出桌宠」关闭整个应用；编辑窗口原生关闭按钮只隐藏编辑器。

齿轮打开「创作工作台」，集中管理角色、对话导入、DeepSeek 连接和本地场景库。语音持续禁用。

## 两条创作路径

### 按角色 Prompt 创作

1. 在编辑窗口点击「角色对象」。
2. 分别给两个角色填写名称与各自的 **User Prompt**：性格、相互关系、说话习惯、希望出现的情节等；保存后重启仍保留。
3. 取消「离线播放」，展开「DeepSeek 连接设置」，保存 API Key 到本机（已从指定文件导入，无需重新输入）。
4. 选择「按角色 Prompt 创作」，填写共同的场景要求，点击「制作并缓存」。导演请求会同时携带两个独立角色对象，逐句标明说话角色、台词、情绪和动作。

角色 Prompt 用于创作，不参与离线生成。既有归档独立保存人物资源、动作命令与构图；编辑角色 Prompt、名字、动作映射或 revision 只影响后续创作。修改归档所引用的模型文件会触发指纹校验错误，需要重新归档。

角色设置保存在 `%APPDATA%/PersonalDuoPet/characters.json`，优先于 config.json 中的名字、User Prompt 和自定义动作。模型路径与语音配置仍从 config.json 读取。

### 导入对话，由 API 编排动作

选择「导入对话，API 编排动作」。可上传 TXT / JSON，也可以直接粘贴。支持 2 至 24 句、每句最多 1000 字。

TXT 每行使用当前角色名或 ID：

```text
角色 A：雨停了吗？
角色 B：停了，我们一起去看彩虹吧！
```

JSON 使用角色 ID，改名后仍能导入：

```json
[
  { "characterId": "companion-a", "text": "雨停了吗？" },
  { "characterId": "companion-b", "text": "停了，我们一起去看彩虹吧！" }
]
```

示例文件见 personal/examples/dialogue.txt 和 dialogue.json。可以附加表演要求，留空时使用自然表演的默认要求。上传文件本身不会调用 API，点击「制作并缓存」才会提交。

**API 只返回逐句动作标注。台词原文、说话角色和顺序由程序保留**，不接受模型改写。重复/缺失的行号会被拒绝，不会保存残缺场景。

## 定时轮播、点击事件与缓存

播放设置在独立编辑窗口的「播放设置」中，保存后立即生效并在重启后保留：

- 「有缓存时定时轮播」默认开启。启动或新场景制作完成后，如果已有可用缓存，立即播放第一段；每段完整结束后默认等待 60 秒，再按本地场景库顺序播放下一段，播完循环。没有生成缓存时回退内置本地示例。间隔可设置为 5 至 86400 秒。
- 「点击角色异步触发本地对话」默认开启。点击人物可见身体或名字会立即取消当前场景，并通过单路异步队列切到下一段，不再等待整段说完。每 800 毫秒最多接受一次点击，连续点击最多保留一个待播事件，不叠加对话或无限排队。场景先预加载需要的表情/动作，每个角色串行执行；被取消的旧场景不能在切换后继续提交延迟动作。
- 单独拖动角色、拖动背景、点击编辑/退出按钮，不触发角色对话。
- 没有可用缓存时保持待机，自动轮播和点击事件不调用生成 API。没有生成缓存时，内置示例也可参与点击与轮播，避免空库时无反应。
- 编辑器的「播放」可手动播放选中场景；「停止」会清除待播事件、停止当前播放并暂停定时轮播。再次手动播放或保存播放设置可恢复轮播。关闭编辑器不影响桌面定时播放。

轮播和点击共用一个异步播放队列，始终只播放一段场景，不会重叠字幕、动作或语音。语音仍保持禁用；即使旧缓存带有音频，当前禁用语音时也只播放字幕与动作。

切换「离线播放」后不调用任何生成服务。缓存位于 `%APPDATA%/PersonalDuoPet/scenes` 和 `audio`，可通过编辑器的「缓存目录」打开。同样的角色设置、创作要求和导入内容会复用已制作场景。API Key 不写入场景缓存。

播放设置保存在用户目录 preferences.json，与离线开关分别保存，不会互相覆盖。

## DeepSeek

默认 `https://api.deepseek.com`，模型 `deepseek-flash`（依 2026-11-16 官方文档）。模型名称可在 config.json 修改。请求使用 `/chat/completions` 和 JSON 输出；内容经过双角色与动作白名单校验。未提供密钥时只能播放预设/已有缓存。

密钥已从 toy/deepseekapi.txt 一次性导入，使用 Electron safeStorage（Windows 系统加密）保存为用户目录 deepseek-key.enc。每次启动自动解密到主进程内存；新开进程已验证可加载。编辑器可通过「保存到本机」更新密钥，页面只获知配置状态，不返回密钥。也支持 DEEPSEEK_API_KEY 环境变量。

## GPT-SoVITS（用户要求：暂不启用、不实机测试）

`tts.enabled` 保持 **false**。已按本机 api_v2.py 的 `/tts`、`/set_gpt_weights`、`/set_sovits_weights` 实现接口，未启动服务、未加载或下载语音权重。等用户导入人物/语音模型后再验证。

本机发现的带 RTX 50 系列支持的目录：
`D:/GPT-SoVITS-v2pro-20250604-nvidia50/GPT-SoVITS-v2pro-20250604-nvidia50`。

以后启用时，用该环境自己的 runtime/python.exe 启动 api_v2.py，不能使用系统 Python 替代。默认地址 `http://127.0.0.1:9880`。两位角色分别填写：

```json
{
  "speech": {
    "refAudioPath": "D:/voices/character-a/reference.wav",
    "promptText": "参考音频对应的原文",
    "promptLang": "zh",
    "textLang": "zh",
    "gptWeights": "D:/voices/character-a/model.ckpt",
    "sovitsWeights": "D:/voices/character-a/model.pth"
  }
}
```

参考音频/权重路径相对于语音服务所在机器。若两人使用同一预训练权重、只靠参考音频区分音色，双方的权重路径都可留空。若使用专门训练的双角色权重，两个人物都需要完整填写 GPT 和 SoVITS 路径，顺序切换并逐句合成。当前不并行合成，避免同一 api_v2 实例的全局权重互相覆盖。制作时不要让其他程序同时切换这个服务的权重。

当前语音关闭，场景库隐藏语音数量；所有验证均未调用 GPT-SoVITS。开启语音并填写音色配置后，重新提交相同创作要求可制作带声音的新场景。已有场景及语音引用保留在归档中，后续角色配置变更不会重写旧表演。

## 人物和动作

`modelPath` 相对项目根目录，例如 `models/live2d/character-a/model.model3.json`，也支持绝对路径。

`actions` 把 Agent 可选的语义动作映射到真实模型的资源：

```json
{
  "happy": {
    "expression": "smile",
    "motion": { "group": "TapBody", "index": 0 },
    "parameters": [{ "id": "ParamAngleZ", "value": 8 }],
    "durationMs": 500
  }
}
```

导入模型后会从 model3.json 自动收集表情和动作组，可在角色对象的「动作映射（高级）」中添加语义别名、描述和参数组合。动作、表情 ID 必须与模型匹配；参数按实际模型范围夹取并渐变释放。当前生成的是已有资源与参数的表演安排，不会生成新 moc3 模型。两个模型已完成实际 MOC/贴图加载和动作执行验证。口型随语音保持待测。

## 表演 Review 与 A 无表情的排查

原上游 `src/agent/handler.ts` 存在最多 10 次的工具调用循环；`agent-plugins/expression-generator/main.js` 在格式解析失败时重试一次。二者都不提供渲染效果反馈审查，而且 personal 入口使用自己的编排运行时。

现在的新场景流程：生成候选 → 规则校验 → 独立语义 Review → 必要时修订 → 再 Review，最多 2 轮审稿。未批准、缺少修订、篡改台词、无效动作或超出重试上限时不发布到场景库。规则要求两个人物都有身体与面部表演、动作时序疏密合理；审稿依据台词、人物设定、真实资源及预设参数风险。记录保存在 scene.review，不会声称云端文字模型看过渲染画面。

已有旧缓存保留并标为“旧版未复审”，自动轮播优先选择已通过 Review 的场景。重新制作同一对话会按新版本重新审稿。

A 表情失效的根因是双模型情况下 Live2D Core 默认内存不足：直接设置眼睛/嘴形参数，A 的网格变化总量曾为 0，而 B 非零。加载模型前调用 `Live2DCubismCore.Memory.initializeAmountOfMemory(128 * 1024 * 1024)` 后，两位模型均有非零网格响应，且实际截图可见 A 的脸部变化。此问题不是 LLM 选择错误。

B 的闭眼大笑、张嘴思考等为原预设自身的强表情。现在表情以每个人物的 presentation 权重叠加，笑/思考单独减弱，语音关闭时限制嘴巴最大张开量。原资源不修改。

当前实际雨后散步 API 结果经过一次修订、两轮 Review：6 句原文完整保留，14 个时间点、6 次身体动作，全部通过实际 SDK。表情自然程度仍由人工观感判断；本地逐预设截图和面部网格敏感性结果见 `.preview/portrait-probe/`，并保存在 reports/portrait-review-diagnostics.json。


## 表演归档与人工局部修订

每个场景对应 `%APPDATA%/PersonalDuoPet/archives/` 下的一个 JSON 对象，schema 为 `personal-duo-performance`、version 为 1。文件名为场景 ID 的 SHA-256。缓存目录按钮打开该目录的上一级。

对象包含 sceneId/revision/published、两个人物的模型定义与资源指纹、动作映射快照、表情表现权重、归一化坐标与缩放、台词、音频缓存引用，以及逐句时间轴。每个时间点同时保存语义动作键和已经解析的 `command`（expression/motion/parameters/durationMs/stopMotion），播放不再读取当前角色的动作映射，也不调用 LLM。坐标相对播放区域保存，窗口尺寸改变时按比例还原。

首次启动自动迁移现有 scenes 缓存与两个内置示例，保留旧文件。旧缓存没有保存完整模型/布局信息，因此按迁移时的角色配置和默认半身布局补齐；迁移后不会再受全局配置变化影响。模型二进制、贴图与音频仍作为本机共享资源引用，不重复嵌入每个 JSON；模型定义和依赖资源包含 SHA-256，播放前检查，归档本身不是可单独分发的模型素材包。

创作流程：

1. 制作场景后先保存草稿，不立即加入轮播。编辑器中选择场景，点击「预览草稿」播放完整场景；也可选择台词后点击「预览选中台词」。预览暂停轮播，停止按钮可以中止。
2. 选择要修改的台词和时间范围（毫秒，包含边界），填写反馈，例如“这句是平静提醒，不要偏头和摇晃，保留微笑”。
3. 点击「定位片段并让 LLM 修改」。云端先真实调用 `inspect_performance_segment`；本地检查调用参数没有越过用户选择，返回该句事件、相邻台词和归档内该人物的可用动作。随后将反馈编成修改 Prompt，让 LLM 返回此范围内的动作补丁。这是一轮工具调用、两次 API 请求。
4. 本地验证补丁时间、动作、顺序与条数，只合并指定范围。原台词、其他句子、范围外命令、人物与构图保持原样；原版归档保留，新版本仍是草稿。工具参数、结果、Prompt、解释和补丁记入 editHistory，可在工作台展开查看。
5. 拖动人物调整构图后，等待预览结束或停止，再点击「保存预览中坐标」。保存会增加修订号，需重新完整预览。完整预览结束后点击「确认并加入轮播」；单句预览和旧修订的预览不能确认新修订。这里的确认仅指本地播放，不是对外发布。

播放器默认会在动作之外叠加呼吸摆动，其中还包括头部 X/Y/Z 与身体角度变化。现将角度摆动权重归档为 presentation.naturalSwayWeight=0，只保留呼吸本身，避免没有编排也在偏头。`still` 动作显式停止身体 motion 并回正，可随后叠加表情；句间保留已有 motion/表情/参数；需要明确停止前一动作时使用 still。场景完成、停止或播放异常后统一过渡至待机。保留用户指定范围外的显式动作，因此如果范围外仍有转向，需要选择对应片段另行修改。人工视觉反馈决定自然程度；规则和语义审稿不能保证渲染观感。

离线允许预览、保存坐标、确认与归档播放；生成和反馈修订需要联网。语音仍关闭。

验证记录：31 项检查通过；`.preview/archive-verification.json` 记录两个真实模型下的归档命令执行、单句/完整预览、坐标保存、旧预览拒绝及确认后轮播恢复。`reports/targeted-revision-result.json` 记录真实 DeepSeek 工具调用：只把雨后散步第 1 句 0ms 的转向替换为 still，其他数据保持不变，修订版仅保存为草稿。原有 3 个生成缓存及 2 个内置示例均已迁移。

局部修订请求显式关闭 DeepSeek thinking，以支持指定函数的 tool_choice；依据 [DeepSeek 官方工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/) 和 [接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。


## 句间衔接与待机（播放器处理）

播放器把人物区分为 speaking（说话）、listening（倾听）和 idle（待机）。说话人轮换时不再重置模型到默认参数，倾听者继续已有姿态；下一条归档动作从上一帧实际显示的姿态平滑接入。显式 still 仍停止身体 motion，但回正过程也会经过平滑过渡。不会自动生成点头或摇头等可能不符合语境的倾听动作。

场景结束、停止、点击切换导致的取消、执行异常后，两位角色停止旧 motion、释放表情和参数覆盖，并逐渐恢复待机，保留呼吸与模型自动眨眼。待机不调用生成 API。已有局部修订工具仍可修改跨句语义不合适的动作；这一轮连续性修复由播放器完成，无需重新生成缓存。

归档 playback 保存 continuityVersion=1、resetBeforeTurn=false、transitionMs=450、idleTransitionMs=900（毫秒）。首次启动自动补齐旧归档。过渡在 Cubism 完成动作、表情与物理计算后混合实际显示参数，不把混合结果写回 SDK 的基础姿态，避免帧间累计漂移；连续打断时从最近已显示姿态重新接入。窗口坐标和布局不受此混合影响。混合参数兼容离线播放与单句预览，语音保持关闭。
